自动化填写问卷（以及爬虫领域）**最核心、也最头疼的技术深水区**。

根据你上一轮提供的问卷星 HTML 源码，我敏锐地观察到了这几个关键参数：
*   `aliyun-captcha-iconfont`
*   `var useAliVerify =0; var captchaType = '2'; var needLoadAliVerify=1;`
*   `<div id="captchaOut">...</div>`

这说明问卷星使用的是**阿里云的防御/验证码系统（Aliyun Captcha）**。通常，当你高频提交时，它会触发**智能无感验证**（如果检测到异常就会弹窗）、**滑块验证**或**点选验证**。

针对 Kotlin + Playwright 的技术栈，要突破或处理这个验证环节，业界通常有以下四种维度的解决方案，按**推荐程度和可行性**由高到低排列：

---

### 方案一：最高级策略——“防患于未然”（降低触发率）

最牛的验证码破解，就是**不让验证码出现**。问卷星的阿里风控是通过检测你的“环境”和“行为”来决定是否弹验证码的。如果你这步做得好，80% 的问卷可以直接“无感”提交。

1.  **注入隐藏指纹 (Playwright Stealth)**
    *   **原理：** 默认的 Playwright 运行在 Headless 模式时，会带有大量的机器特征（如 `navigator.webdriver = true`）。风控系统一秒钟就能识别出你是机器人。
    *   **Kotlin 实现思路：** 在 Java/Kotlin 中，没有像 Python 那样现成的 `playwright-stealth` 库。你需要手动在每次创建 `Page` 时注入消除特征的 JS 脚本（可以使用 `page.addInitScript()`）。
    *   **核心要抹除的特征：** `webdriver`、`plugins` 伪装、`languages` 伪装、WebGL 图像指纹等。
2.  **IP 代理池池化 (Proxy Rotation)**[这一步暂时不管，毕竟软件能用再说]
    *   **原理：** 同一个 IP 提交 3 份以上，100% 触发最高级别验证码。
    *   **实施：** 购买高质量的**动态住宅 IP (Residential Proxies)**。在并发架构中，为每一个 `BrowserContext` 分配一个全新的动态 IP。
3.  **拟人化行为注入 (Human-like Behavior)**
    *   不要瞬间点击完所有选项！每次 `click()` 之前加入 300ms-1500ms 的随机停顿。
    *   提交前，模拟页面滚动 (`page.mouse().wheel()`)。

---

### 方案二：针对“滑块验证码”的轨迹模拟（硬核算法）

如果验证码必须出现，大概率是阿里云的**拖动滑块验证**。阿里云对滑块的**拖动轨迹（Track）**有着极高要求的机器学习检测。直线匀速拖动必死。

**Kotlin + Playwright 模拟拖动算法要点：**
1.  **定位滑块与滑块轨道：** 获取滑块按钮 (Slider) 的 BoundingBox，以及要滑动的总距离 (Distance)。
2.  **生成拟人轨迹 (Ease-out 曲线)：**
    *   人手的拖动特征是：**起步慢 -> 中间加速 -> 临近终点减速 -> 甚至滑过了再拉回来一点 -> 产生垂直方向(Y轴)的细微抖动**。
3.  **Playwright 鼠标事件模拟 (Kotlin 伪代码示例)：**

```kotlin
// 1. 获取滑块元素
val slider = page.locator("#nc_1_n1z") 
val box = slider.boundingBox()

// 2. 将鼠标移动到滑块中心
page.mouse().move(box.x + box.width / 2, box.y + box.height / 2)
page.mouse().down()

// 3. 模拟轨迹分段滑动 (假设总距离需滑动 300px)
var currentX = box.x
val endX = box.x + 300
val startY = box.y + box.height / 2

// 生成一个非匀速的轨迹数组 (你需要自己写一个缓动算法生成这些点)
val tracks = generateHumanTracks(300) 

for (step in tracks) {
    currentX += step
    // Y轴加入随机抖动 (-2 到 2 像素)
    val randomY = startY + (Math.random() * 4 - 2)
    
    // Playwright 鼠标移动，设置随机步数
    page.mouse().move(currentX, randomY, MouseMoveOptions().setSteps(2)) 
    
    // 每步之间加入 10-30ms 的随机停顿
    Thread.sleep((10..30).random().toLong()) 
}

// 4. 释放鼠标
page.mouse().up()
```

### 方案三：对接第三方打码平台 (针对点选/图中选字)

如果阿里风控升级，弹出了“请依次点击图中的‘机、器、人’三个字”，这就超出了单纯写代码能解决的范畴了。

*   **对策：** 使用市面上的商业打码/AI识别 API（如 2Captcha、图鉴、YesCaptcha 等）。
*   **流程：**
    1. 当 Playwright 侦测到特定的验证码弹窗出现时。
    2. 使用 `page.locator("#captcha-image").screenshot()` 截取验证码图片。
    3. 通过 HTTP 客户端将图片 Base64 发送给打码平台。
    4. 平台返回需要点击的坐标数组 `[{x: 120, y: 30}, {x: 45, y: 90}]`。
    5. Playwright 根据坐标执行 `page.mouse().click(x, y)`。

### 方案四：半自动化（人机协同 fallback）

考虑到你目前的并发是 5，问卷数是 100。如果你只是自己用或者非大型商业项目，**完全没必要死磕极高难度的验证码逆向**。

*   **对策：** 开启有头模式（Headless = false），或者在无头模式下通过 WebSocket 将页面截图推到你的控制台。
*   **流程：**
    1. 点击“提交”后，系统监听特定的成功标识（如页面跳转、出现“感谢参与”文本）。
    2. 如果 `page.waitForSelector(".success-msg", timeout = 3000)` 超时，说明卡住了（大概率是验证码）。
    3. 程序通过提示音或日志报警：“线程 3 遇到验证码，请手动处理”。
    4. 协程挂起 `delay`，等待你去浏览器里手动滑一下验证码。
    5. 手动通过后，程序检测到成功，继续领下一个任务。
